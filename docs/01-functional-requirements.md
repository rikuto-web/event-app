# 機能要件

## 1. 目的

複数ユーザーがイベント情報を共同管理し、編集・コメント・参加表明をリアルタイムで共有できる Web アプリケーションを提供する。

## 2. 対象ユーザー

| ユーザー種別 | 説明 |
| --- | --- |
| 未認証ユーザー | ログイン・新規登録のみ可能 |
| 認証済みユーザー | イベントの作成、共有、編集、コメント、参加表明が可能 |

## 3. 機能一覧

| ID | 機能 | 概要 |
| --- | --- | --- |
| F-01 | ユーザー登録 | メールアドレス・表示名・パスワードでアカウント作成 |
| F-02 | ログイン / ログアウト | JWT（アクセス + リフレッシュ）による認証 |
| F-03 | イベント一覧 | 自分が関与するイベントを **カレンダー（月表示・既定）** または **スケジュール（24h タイムライン）** で表示。ロールでフィルタ |
| F-04 | イベント詳細 | 日時・場所・説明・画像・メンバー・参加状況・コメントを表示 |
| F-05 | イベント作成 | タイトル・説明・開始/終了日時・場所・画像を登録。作成者を owner とする |
| F-06 | イベント編集 | owner / editor が基本情報を更新。他メンバーへリアルタイム反映 |
| F-07 | イベント削除 | owner のみ物理削除（メンバー・コメント・参加表明も CASCADE） |
| F-08 | メンバー招待 | owner が他ユーザーを editor または viewer として追加 |
| F-09 | メンバー権限変更 / 削除 | owner がロール変更またはメンバー除外 |
| F-10 | 参加表明 | 認可されたメンバーが「参加する / 未定 / 不参加」を設定（[用語](#12-用語) 参照） |
| F-11 | コメント | 認可されたメンバーがイベントにコメント投稿 |
| F-12 | リアルタイム同期 | イベント更新・コメント・参加表明を WebSocket で他メンバーへプッシュ |
| F-13 | 画像アップロード | イベント画像を Object Storage に保存し URL を DB に保持 |

## 4. 対象外（本次）

| 項目 | 理由 |
| --- | --- |
| 外部カレンダー連携（Google Calendar 等） | スコープ外。将来拡張 |
| メール通知・リマインダー | スコープ外 |
| 組織 / テナント機能 | 個人〜小規模チーム利用を想定 |
| イベントの公開 URL（未ログイン閲覧） | 認証必須とする |
| 動画・大容量ファイル | 画像（JPEG / PNG / WebP）のみ |
| モバイルネイティブアプリ | Web のみ |

## 5. エンティティ制約

### 5.1 User（ユーザー）

| 項目 | 制約 |
| --- | --- |
| email | 必須、一意、RFC 5322 相当の形式、最大 254 文字 |
| display_name | 必須、1〜50 文字 |
| password | 登録時必須、8〜72 文字（bcrypt でハッシュ保存） |

### 5.2 Event（イベント）

| 項目 | 制約 |
| --- | --- |
| title | 必須、1〜100 文字 |
| description | 任意、最大 2000 文字 |
| starts_at | 必須、ISO 8601 日時 |
| ends_at | 必須、`starts_at` 以降 |
| location | 任意、最大 200 文字 |
| image_object_key | 任意、Object Storage 上のキー |
| owner_id | 必須、User への FK |

### 5.3 EventMember（メンバー）

| 項目 | 制約 |
| --- | --- |
| event_id + user_id | 一意 |
| role | `owner` / `editor` / `viewer` のいずれか |
| owner | イベントあたり 1 名（作成者）。削除不可 |

| ロール | 閲覧 | 編集 | コメント | 参加表明 | 招待 / 権限管理 | 削除 |
| --- | --- | --- | --- | --- | --- | --- |
| owner | ○ | ○ | ○ | ○ | ○ | ○ |
| editor | ○ | ○ | ○ | ○ | × | × |
| viewer | ○ | × | ○ | ○ | × | × |

未招待ユーザーはイベントにアクセスできない（404 相当）。

### 5.4 EventComment（コメント）

| 項目 | 制約 |
| --- | --- |
| body | 必須、1〜500 文字 |
| author_id | 必須、メンバーであること |

コメントの編集・削除は **投稿者本人のみ**（owner でも他人のコメントは削除不可）。

### 5.5 EventParticipation（参加表明）

| 項目 | 制約 |
| --- | --- |
| status | `going` / `maybe` / `not_going` |
| event_id + user_id | 一意（メンバー 1 人 1 ステータス） |

### 5.6 画像

| 項目 | 制約 |
| --- | --- |
| 形式 | JPEG / PNG / WebP |
| サイズ | 最大 5 MB |
| 保存先 | OCI Object Storage（DB には URL / キーのみ） |

## 6. 検索・フィルタ（イベント一覧）

> **プロトタイプ反映**: キーワード検索（`q`）は採用しない。一覧 UI はカードグリッドではなくカレンダー / スケジュール切替。

### 6.1 共通（ツールバー）

| パラメータ | 説明 |
| --- | --- |
| role | `owner` / `member`（自分が owner のもの / 招待されたもの）。空はすべて |
| view | `calendar`（既定）/ `schedule` |

フィルタ条件は URL の search params に同期する。

### 6.2 カレンダー表示（`view=calendar`）

| パラメータ | 説明 |
| --- | --- |
| month | 表示月（`YYYY-MM`）。省略時は当月 |

| 挙動 | 説明 |
| --- | --- |
| 月ナビ | 前月 / 翌月 / 今月 |
| セル表示 | 1 日あたり最大 **2 件**までチップ表示。超過分は「他 N 件」 |
| 日付クリック | 0 件 → 新規作成モーダル / 1 件 → 詳細 / 2 件以上 → 当日一覧モーダル |
| 日付番号クリック | その日を開始・終了日時の既定値（10:00–12:00）にした新規作成モーダル |
| 当日一覧モーダル | 時刻順リスト、詳細リンク、「この日に作成」 |

### 6.3 スケジュール表示（`view=schedule`）

Teams 風の **24 時間縦タイムライン**。複数日は横に並列表示。

| パラメータ | 説明 |
| --- | --- |
| from | 表示開始日（`YYYY-MM-DD`）。省略時は当日 |
| to | 表示終了日（`YYYY-MM-DD`）。省略時は `from` と同日 |

| 制約・挙動 | 説明 |
| --- | --- |
| 期間上限 | `from` から最大 **7 日間**（`to` は自動 clamp） |
| フィルタ | イベントの `[starts_at, ends_at)` が表示期間と **1 秒でも重なる**ものを表示 |
| ナビ | ← / → は現在の表示日数分をシフト、**今日** は当日 1 日にジャンプ |
| 現在時刻 | 表示範囲に当日が含まれるとき、赤線で現在時刻を表示し、概ね 2 時間前付近へ自動スクロール |
| 空状態 | イベント 0 件でも **「この期間にイベントはありません」等のメッセージは出さない**（グリッドのみ） |

### 6.4 API 側（一覧取得）

| パラメータ | 説明 |
| --- | --- |
| from / to | スケジュール表示向け。期間との **重なり** で絞り込み（[06 API](06-api.md)） |
| sort | `starts_at_asc`（既定）/ `starts_at_desc` / `updated_desc`。**UI では v1 未提供**（API のみ） |

`view` / `month` はフロントのルーティング専用。API は全関連イベントを返し、カレンダーの月切替はクライアント側で日付マッピングする。

## 7. 作成・更新の単位

| 操作 | 単位 |
| --- | --- |
| イベント作成 | 親（Event）を 1 リクエストで作成。owner メンバー行を同時 INSERT |
| イベント基本情報更新 | Event を PUT |
| メンバー追加 | 行単位 POST |
| メンバー権限変更 | 行単位 PATCH |
| メンバー削除 | 行単位 DELETE（owner 以外） |
| コメント | 行単位 POST（編集・削除は PATCH / DELETE） |
| 参加表明 | 行単位 PUT（upsert） |

## 8. 削除方針

- イベント: **物理削除** + CASCADE（members / comments / participations）
- コメント: 投稿者による物理削除
- 画像: イベント削除時に Object Storage オブジェクトも削除（ベストエフォート）

論理削除は採用しない。

## 9. バリデーション分担

| 層 | 担当 |
| --- | --- |
| フロントエンド | 必須入力、文字数、日時の前後関係、画像形式・サイズ |
| バックエンド | 同上 + 認可（ロール）、一意制約、存在チェック |

## 10. エラー時の画面挙動

| 状況 | 画面 |
| --- | --- |
| 401 | ログイン画面へリダイレクト（トークンリフレッシュ失敗時） |
| 403 | トーストで権限エラー。詳細画面は閲覧のみ表示 |
| 404 | イベント未存在または非メンバー → 一覧へ誘導 |
| 422 | フォームにフィールドエラー表示 |
| 409 | 重複 email 等をフォーム上部に表示 |
| 5xx | 汎用エラートースト + 再試行 |

## 11. UX 最低限

- 送信ボタンの二重クリック防止（loading 状態）
- 削除・メンバー除外前に確認ダイアログ
- **新規作成**は一覧（S-03）上の **モーダル**。キャンセルはモーダルを閉じる（一覧に留まる）
- **編集**は別画面（S-06）。キャンセルは **直前の画面**（詳細）へ戻る
- 詳細画面表示中は WebSocket で変更を受信（切断時は指数バックオフで再接続、最大 30 秒間隔）
- 自分の操作（コメント投稿・参加表明）は送信成功時に即座に UI 反映。他ユーザー分は WebSocket で受信
- 一覧の既定表示は **カレンダー（月）**。スケジュールタブで 24h タイムラインに切替

## 12. 用語

| 用語 | 説明 |
| --- | --- |
| RSVP | **R**épondez **s**'il **v**ous **p**laît（フランス語「ご返事ください」）の略。イベント管理では「参加するかどうかの返事」を指す慣習的な呼び方。本アプリでは UI 上「参加する / 未定 / 不参加」の 3 択（API 上は `going` / `maybe` / `not_going`）として実装する |
| WebSocket | ブラウザとサーバー間の双方向常時接続。イベント詳細のコメント・参加表明を即時反映するために使用 |
